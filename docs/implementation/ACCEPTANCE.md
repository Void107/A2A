# 改造验收规格

本文是未来实现的验收要求，不是测试报告。所有条目初始状态均为 `NOT_RUN`；文档和样例校验通过不能代替运行时验收通过。

## 执行与证据规则

- 使用 [契约草案](CONTRACT_SPEC.md) 和 [合成样例](examples/README.md)；`spec_version=0.3.0-draft.1`、`contract_version=1.0.0`。
- Given 表示前置条件，When 表示触发动作，Then 表示必须观察到的结果；每个条目的正例和反例都要执行。
- AC-01 至 AC-21、AC-23、AC-24 是机器门槛；AC-22 是真实参与者试用门槛，不能用代理自测替代。
- 集成验证使用真实 PostgreSQL、OPA 和 Presidio；Redis 如启用也使用真实实例。替身仅用于定位故障和精确控制竞态，不能代替成功路径集成证据。
- 所有样本均为英文合成会议，邮箱使用 `example.com`；访问仅限测试容器或显式批准的本地服务，不触达真实内网、云元数据、外部人员或生产数据。
- 每次执行记录 AC 编号、提交标识、环境及依赖版本、命令、时间、退出码、断言摘要和证据路径。保留失败输出，但不得记录密钥或敏感原文。
- 更新状态只能使用 `NOT_RUN`、`PASS`、`FAIL`、`BLOCKED`；有环境限制时记录原因与下一步，不把未执行写成通过。AC-22 未招募参与者时保持 `NOT_RUN`，注明 `pending: awaiting participant`。
- 未来执行者创建实际结果记录；本轮不创建伪造运行记录。不可适用的检查要解释边界，不静默跳过必需门槛。
- 实际验收状态写入 TASKS.json 的 acceptance_results；本文的“初始状态”保持需求基线，避免维护两份互相矛盾的运行状态。

## AC-01 契约发布静态校验

类型：自动；初始状态：`NOT_RUN`。
Given：合法会议契约及独立变体：错误 effect、未知条件、重复 ID、缺失 processor、非法路径、未知规范版本、远程引用、未支持语言或实体。
When：分别提交草案校验及激活请求，包括伪造客户端 `validated` 标记的请求。
Then：合法契约可激活；每个非法变体返回稳定错误和安全的定位信息，数据库中不能留下 active 版本。
反例：不能因发现 `schemas` 或 `views` 字段存在就通过；不能忽略未知条件、自动降级或执行任意脚本。
证据：参数化负例清单、服务端激活检查、不可变契约摘要与版本记录。

## AC-02 可信组织与身份

类型：自动；初始状态：`NOT_RUN`。
Given：管理员登记的内部主体、合作主体，以及自行声称属于受信组织的未授权主体。
When：请求登录、注册、发现和交付；另测缺失、篡改、过期凭证与被停用主体。
Then：仅服务端可信登记产生有效组织和角色上下文；合作主体不能通过填写内部 domain/role 获得内部视图。
反例：有效签名 JWT 中的旧角色或自述用途不能覆盖当前权限；匿名注册不能自行授予管理员身份。
证据：正反身份矩阵、拒绝状态、实际用于决策的上下文摘要，不保存明文凭证。

## AC-03 接口权限与数据隔离

类型：自动；初始状态：`NOT_RUN`。
Given：管理员、内部 Agent、合作 Agent、无 scope 的有效登录主体，以及不同所有者的审计记录。
When：访问发现、查询、契约发布、审计查询和公开通知接口，包括省略审计筛选参数。
Then：分别执行所需 scope 与资源权限；发现只列可见视图，合作主体不能查询全局审计或发布他人契约。公开通知只接受批准事件及可公开资源的 ID/版本元数据，任意 content/自由文本请求必须被拒绝。
反例：登录成功不代表拥有全部接口权限；广播不能成为敏感会议数据的旁路。
证据：接口授权矩阵；第一版通知限制为公开内容的可执行检查和文档边界一致。

## AC-04 上游身份与回调地址边界

类型：自动；初始状态：`NOT_RUN`。
Given：受控上游校验器、批准的地址，以及模拟重定向、地址解析变化和未批准目标的本地测试配置。
When：发送合法签名请求，并发送被篡改正文、过期时间戳、重放 nonce、未知密钥标识和非法地址请求。
Then：上游只接受有效且未重放的签名请求；Hub 在连接前执行地址策略，重定向不能绕过地址检查。
反例：不得从 bcrypt 哈希“恢复”签名密钥；拒绝地址测试不得向真实内网或云元数据发送探测请求。
证据：本地上游接收次数、签名正反例及地址策略测试；测试服务例外须显式限于测试配置。

## AC-05 OPA 明确决策与义务

类型：自动；初始状态：`NOT_RUN`。
Given：真实 OPA 和固定策略模板；内部、合作、无匹配、deny 与 allow 同时匹配的身份组合。
When：请求不同视图，另注入 HTTP 200 但 result 缺失/null/空对象、allow 非布尔值或契约摘要不一致的响应。
Then：仅完整、类型正确且绑定当前契约/视图的显式允许能继续；deny 优先，无匹配拒绝，不同身份维度采用 AND。
反例：多个 allow 不得减少视图必需 processor；OPA 允许不能覆盖 Hub 固定的交付校验义务。
证据：真实策略测试和 Hub 适配测试；明确展示未定义决策没有触发上游取数。

## AC-06 OPA 超时与不可用

类型：自动；初始状态：`NOT_RUN`。
Given：先成功交付并预热缓存，再分别停止 OPA、延迟响应、返回错误状态或不合法 JSON。
When：请求需要授权的视图，并在调用中途恢复 OPA。
Then：故障期间在配置时限内拒绝交付并返回稳定错误；恢复后新请求重新授权并成功。
反例：不能复用过期允许结果、切换宽松本地规则或返回未经检查的旧缓存数据。
证据：超时边界、依赖调用次数及失败响应；不得将 HTTP 层可达等同于策略服务就绪。

## AC-07 确定性字段处理

类型：自动；初始状态：`NOT_RUN`。
Given：原始会议数据及两个独立请求，分别指定 internal-project 与 external-collaboration。
When：经真实查询入口执行投影，再颠倒请求顺序重复执行。
Then：内部保留 owner_name/owner_email；外部彻底不含两字段；数组数量、顺序、item_id 与截止日期对应关系不变。
反例：不能删除键后保留嵌套副本；不能修改共享输入导致内部请求获得已经被外部处理过的数据。
证据：与两份 expected 文件的精确 JSON 比较；测试调用生产使用的同一处理入口。

## AC-08 Presidio 基线范围

类型：自动；初始状态：`NOT_RUN`。
Given：锁定版本和 profile 的真实 Presidio；在 title、summary、每个 action_items[*].task 中分别插入已标注英文邮箱。
When：请求外部视图，并另测无邮箱文本、多个邮箱和标点紧邻的固定回归样例。
Then：基准中的邮箱片段全部替换为 `[EMAIL]`，其他字符保持不变；未投影字段不发送给识别器。
反例：不能遗漏 title；不能允许 meeting_id/item_id 夹带自由文本，due_date 必须实际执行日期格式校验。
证据：`en + EMAIL_ADDRESS` 的模型/识别器/阈值/profile revision、输入标注与实际片段结果。

## AC-09 检测质量与能力边界

类型：自动报告；初始状态：`NOT_RUN`。
Given：分离的固定回归集和合成探索集，含邮箱正例、相似但无邮箱的负例，以及 PERSON/中文/电话边界样本。
When：运行锁定 profile，对实体片段计算 TP、FP、FN；同时记录替换后下游任务能否使用。
Then：固定承诺样例零漏处理、无邮箱负例不被改写；探索集如实报告 precision/recall、样本量及误检漏检，不以探索失败扩张能力承诺。
反例：不得写“已匿名化所有身份”；自由文本中的人名可仍存在，PERSON/中文/电话不计入已支持实体，不能以真实个人数据补充样本。
证据：可复现标注集、逐例差异和分母；在激活未知语言/实体时拒绝，而非运行时悄悄忽略。

## AC-10 原始数据结构漂移

类型：自动；初始状态：`NOT_RUN`。
Given：合法原始数据，及新增 secret 字段、嵌套新增字段、数组变对象、缺少 owner_email、非法日期等变体。
When：由受控上游返回这些数据，包括故意把邮箱放进标识字段的情况。
Then：合法数据继续处理；不符合 source_schema 的数据在投影前整体拒绝，不交付“删掉异常字段后”的部分结果。
反例：只验证输出结构不能代替原始结构校验；schema 中 format 不能仅作为描述而不执行。
证据：每个变体的拒绝代码及未发生交付的断言。另测结构合法但响应 meeting_id 与请求不一致，应返回 UPSTREAM_RESOURCE_MISMATCH；请求未批准的会议必须在取数前拒绝，query 缺失或多余键拒绝。

## AC-11 交付结构与处理完整性

类型：自动；初始状态：`NOT_RUN`。
Given：必需 processor 清单及合法输出 schema；注入漏执行、处理异常、缺字段、字段类型变化和新增字段。
When：进入交付前校验，包括输出恰好“看起来正常”但 processor 未完成的情况。
Then：只有结构校验和全部必需处理完成同时成立才可继续；处理器不可用不能返回原值。
反例：字符串工资区间不能冒充数字 salary；第一版不支持的转换在发布时拒绝，不靠测试自制新处理器实现。
证据：输出 schema 断言、处理完成清单和失败路径；空命中结果与未执行必须明确区分。

## AC-12 两种视图的下游任务

类型：自动；初始状态：`NOT_RUN`。
Given：两个真实运行的本地下游消费者，按 consumer.requirements.json 使用生产返回结果。
When：内部消费者创建并按 owner_email 分配行动项；外部消费者导入待分配行动项。
Then：各创建两项，保持任务内容与日期；内部正确分配 Alice/Bob，外部为 unassigned 且不需要猜测负责人。
反例：删除内部 owner_email 或打乱日期配对应使任务验证失败；只断言 JSON 有效不足以通过。
证据：本地任务存储的最终状态；不得向真实任务平台、邮箱或其他人员发送消息。

## AC-13 故障与资源边界

类型：自动；初始状态：`NOT_RUN`。
Given：可控制延迟、响应大小和 JSON 格式的本地上游，以及必需 Presidio 服务的停止/超时故障。
When：发送超大、非法 JSON、慢速持续读取、并发超限请求，并在响应处理中触发必需服务失败。
Then：响应受系统与契约中更严格的大小、总时限和并发上限约束；稳定报错，未验证内容一字节也不提前交付。
反例：分段读取不断收到字节不能无限延长总时限；异常信息不能携带原始数据、内部地址或密钥。
证据：边界上下各一例、并发故障测试、调用方收到的字节和资源释放情况。

## AC-14 撤权覆盖旧版本与缓存

类型：自动；初始状态：`NOT_RUN`。
Given：有效身份已预热发现/策略/结果缓存，持有旧 JWT 和可访问的 contract_version=1.0.0；另准备角色和主体不变、仅撤销该视图或会议资源 grant 的变体。
When：管理员提交撤权，再用旧版本、旧凭证和缓存请求；另在处理即将交付时用同步屏障插入撤权。
Then：撤权提交后新的交付授权检查必须拒绝；检查与交付许可持久化须定义原子顺序，不能留下检查通过后任意延迟的放行窗口。
反例：激活旧契约、回滚默认版本、重复请求或发现结果都不能恢复已撤销权限；已发出的字节无法收回，不作追溯保证。
证据：可复现并发屏障、授权修订号和持久化顺序；不以不可控 sleep 偶然跑过代替竞态验证。

## AC-15 交付前持久化

类型：自动；初始状态：`NOT_RUN`。
Given：真实 PostgreSQL，且交付要求 audit_required=true；可在事务提交前故障或回滚。
When：成功完成处理后写入 receipt 与 outbox，再测试 PG 不可用、提交失败和提交前进程退出。
Then：同一事务提交 receipt/outbox 后才允许返回成功数据；事务未成功时不交付，恢复后不出现半条持久化记录。
反例：日志打印成功、Redis publish 成功、内存排队成功均不满足门槛；PG 失败时不能声称拒绝日志已持久化。
证据：数据库记录、事务失败注入和调用方收到的响应，不只检查 emit 函数被调用。

## AC-16 outbox 恢复与并发幂等

类型：自动；初始状态：`NOT_RUN`。
Given：已提交待处理 outbox，真实 PostgreSQL，Redis 如启用仅用于唤醒；两个或更多消费者。
When：停止 Redis、丢弃唤醒、消费者在处理前后退出、暂时使审计写入失败，然后恢复运行。
Then：轮询补偿能恢复处理；未成功事务不能删除来源记录；并发/重复事件通过事件 ID 幂等，不污染最终审计记录。
反例：Redis 不可用不能造成已提交交付记录丢失；失败批次不能被当成成功确认。
证据：事件总数核对、重试/故障记录、重复消费结果；只承诺可恢复处理，不承诺 exactly-once 网络交付。

## AC-17 交付记录真实性与隐私

类型：自动；初始状态：`NOT_RUN`。
Given：允许、拒绝、处理失败、提交成功后客户端断开，以及客户端重试的请求。
When：查询有权查看的交付记录，并检查普通日志与错误响应。
Then：记录包含请求、契约版本/摘要、视图、策略与 profile revision、处理和验证结果；receipt 表示获准尝试交付，不能标成客户端确认收到。
反例：重试产生新 request_id 并重新授权；不记录原文、识别片段、明文凭证，也不能以字符串扫描无邮箱替代隐私字段设计。
证据：各状态对应记录与日志断言，敏感调试字段默认关闭，未持久化故障如实标记。

## AC-18 官方 A2A SDK 互操作

类型：自动；初始状态：`NOT_RUN`。
Given：固定官方 A2A SDK 与协议版本，两个本地独立进程及正式扩展声明/协商配置。
When：通过官方客户端发现 Agent Card，协商契约扩展，请求两视图，并触发拒绝和不支持扩展请求。
Then：真实 Message/DataPart/Artifact 或所选版本合法类型承载契约语义；成功与错误均能由官方客户端解析，必需扩展不支持时明确失败。
反例：仅通过自定义 REST、手工 HTTP 或内部函数调用不能记为 A2A 通过；同进程假客户端不足以证明互操作。
证据：锁定版本、进程启动步骤、脱敏协议记录和完整结果，使用官方受支持的发现路径。

## AC-19 契约版本与变更比较

类型：自动；初始状态：`NOT_RUN`。
Given：不可变 1.0.0 及派生草案：原样版本、新独立视图、删字段、改类型、改必填项、改投影、改授权和改识别器配置。
When：执行差异检查、激活、指定旧版本查询，并在请求中途激活新默认版本。
Then：相同定义和不影响既有消费者的新视图可报告 compatible；破坏已登记需求时报 breaking；无法确定影响时为 review_required。
反例：字段新增并非总是兼容；权限扩张/收紧和识别器更新单独标为行为/安全变化；不能覆盖已激活版本或混用两个快照。
证据：前后摘要、按视图差异、状态与理由，契约版本和规范版本分别记录。

## AC-20 消费者依赖与发布检查

类型：自动；初始状态：`NOT_RUN`。
Given：已登记的内部/外部消费要求，以及一个未登记消费者的契约副本。
When：移除 owner_email 或更改 due_date 类型，运行登记消费样例与发布门槛；另离线检查旧契约歧义规则。
Then：内部自动分配失败被准确归因；外部是否受影响按实际依赖判断；未登记时只报告结构影响，未知旧语义输出迁移错误。breaking 不能自动切换默认版本；review_required 阻止激活；新主版本通过独立消费与迁移验证后可显式并行激活，旧消费方固定旧版仍受当前授权约束。
反例：不能声称找出全部下游影响，不能自动激活迁移草案，也不能在新引擎失败后回退旧接口放行。
证据：消费者结果、发布阻止原因和迁移诊断；旧接口如保留必须经过同一安全核心。

## AC-21 全新环境独立运行

类型：自动；初始状态：`NOT_RUN`。
Given：没有已有数据库、隐式环境变量、模型缓存或开发者私有配置的临时环境。
When：依 README 配置示例、取得锁定依赖和模型、启动服务、执行迁移和双 Agent 示例，再重启服务。
Then：步骤可复现，健康/就绪检查能识别缺模型与未迁移状态，重启保留已提交数据；只用合成数据与本地服务。
反例：不得依赖个人绝对路径、未声明系统包、默认生产密钥或手动修改 Hub 源码；离线缺依赖应明确 BLOCKED。
证据：干净环境描述、完整步骤、依赖获取成本及成功结果；清理仅删除本次专用测试资源。

## AC-22 新人真实试用

类型：人工产品门槛；初始状态：`NOT_RUN`；试用证据：`pending: awaiting participant`。
Given：一名未参与实现的真实开发者、公开 README 与合成示例；招募和参与时间由用户安排。
When：参与者独立完成启动、接入提供方、获取两视图、理解拒绝原因并修改一项契约。
Then：记录依赖安装时间、实际接入时间、卡点、求助次数及任务结果；常规接入不改 Hub 源码，不要求阅读内部策略实现。
反例：Codex 自测或作者重跑不能替代此证据；无参与者时不得把状态改 PASS，也不阻止继续完成其他独立机器门槛。
证据：经参与者允许记录的观察表和问题修复；试用未完成时发布说明必须写明尚未验证接入体验。

## AC-23 延迟与可靠性测量

类型：自动报告；初始状态：`NOT_RUN`。
Given：锁定硬件/容器资源、负载脚本、数据大小、并发量、热身次数、至少 100 次有效请求和全部失败计数。
When：分别运行内部/外部视图，记录冷启动与预热后延迟，并测并发 1、5、10 的本地受控负载。
Then：分别报告端到端及授权、上游、检测、校验、PG 提交的 p50/p95、吞吐、超时率、错误率和样本量；不删除失败来美化分位数。
反例：不能把本机均值称为生产容量；不能在测量前承诺“数百 Agent”；p99 样本不足时不作稳定性判断。
证据：可复现原始测量与配置，所有请求遵守配置总时限；性能目标待基线与真实场景确认后再成为数值发布门槛。

## AC-24 自动化收集与发布证据

类型：自动及文件检查；初始状态：`NOT_RUN`。
Given：统一测试入口、机器可读依赖锁定、真实服务集成任务和本文所有机器 AC 到测试的映射。
When：在 CI 收集并执行测试，检查被跳过测试、故障退出码、开源许可证与维护文档。
Then：安全反例确实被默认收集，生产入口被覆盖；必需失败/未运行项不能产生绿色发布结论，实际结果逐项可追溯。
反例：不能以测试函数总数、仅 SQLite/FakeRedis 通过或文档链接校验代替核心验收；不得把缺失真实 SDK 检查标为可忽略。
证据：CI 报告、AC 映射、LICENSE、贡献/安全报告流程、变更与限制说明；人工 AC-22 单独展示，未完成不宣称成熟开源。
