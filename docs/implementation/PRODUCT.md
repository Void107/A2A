# A2A 数据契约执行层：产品定义与第一版范围

> 状态：实施设计草案；本文描述目标行为，不代表现有代码已经实现。
> 适用项目：外层 `a2a-contract-hub`；内层历史项目仅供对照，不作为实施目标。
> 当前代码基线称为 legacy 0.2；目标草案使用 `spec_version: 0.3.0-draft.1`、示例 `contract_version: 1.0.0`。
> 这两个版本分别标识契约语言和具体契约，不表示软件已达到稳定版。

## 1. 产品定位

A2A 数据契约执行层让 Agent 在调用前了解可申请的数据视图，在交付前验证实际结果符合约定。
开发者声明数据结构、交付视图、授权约束及必需处理；系统统一执行身份检查、策略决定、数据处理、结构校验和记录。
第一版服务于部署在同一受控环境里的 Agent 集成，不承诺覆盖任意 Agent 通信。
最小可用成果是一个可重复运行的会议数据示例，以及能接入第二个同类数据源的公开接口。
OPA 和 Presidio 是组成能力；项目价值在于减少它们与身份、结构、版本及交付流程之间的集成工作。

## 2. 三个产品问题与验收指标

以下数字均为待验证的验收目标，不能写成已经取得的产品指标。

| 产品问题 | 目标 | 验证方法 |
|---|---|---|
| 接入是否更省事 | 常规接入不修改 Hub 源码，不要求用户编辑 Rego | 独立开发者依照 README 完成提供方和两个调用方的示例 |
| 数据是否仍然可用 | 两个视图均通过各自输出结构及消费样例 | 在固定样本集上检查字段、类型、必填项，并执行下游任务 |
| 变更和故障能否提前发现 | 列明的不兼容变更及必要组件故障全部得到预期处理 | 在发布检查与真实服务故障测试中逐条验证 |

接入试验记录准备环境、下载依赖、配置业务接口、定位错误的独立耗时及求助次数。
在依赖已经可用的条件下，以 30 分钟完成示例作为首次易用性试验目标；未达标应修复文档或流程。
确定性结构处理的固定样本必须全部符合预期；不能用文本识别准确率替代结构校验。
文本检测单独报告样本数、漏检和误检；有限样本通过不代表现实数据零泄露。
所有被支持的故障场景必须做到必需步骤失败时不返回业务数据，不允许回退到旧引擎放行。

## 3. 用户、角色与信任来源

| 角色 | 主要工作 | 权限边界 |
|---|---|---|
| 部署管理员 | 配置可信身份、预注册 Agent、维护允许访问的提供方地址 | 管理权限明确授予，不由 Agent 自行声明 |
| 数据提供方开发者 | 发布有版本的契约，提供符合输入结构的数据接口 | 只能管理获授权的数据资源 |
| 内部项目 Agent | 获取执行项目任务需要的行动项和负责人信息 | 仅访问管理员授权的视图 |
| 外部协作 Agent | 获取合作任务需要的行动项和截止时间 | 作为预注册合作方接入，不信任其自报组织信息 |
| 维护者或审计人员 | 查看获授权的交付记录和故障信息 | 不默认拥有全局查询权，不读取记录中的敏感原文 |

第一版采用单组织受控部署；合作方 Agent 由本组织管理员预注册并明确授予视图访问权。
组织、角色和授权来自受控存储；JWT 签名仅证明令牌完整性，不证明自填组织字段真实。当前视图/会议资源授权独立于契约版本，角色不变也可单独撤销某项访问；旧契约不能恢复它。
用途描述只能帮助理解请求，不能让调用方通过自行填写用途获得额外权限。
开放注册、跨组织身份联邦和自动建立合作关系明确延期。

## 4. 首个场景：会议数据的双视图交付

示例全部使用合成英文会议数据，不使用真实员工或客户数据。
提供方返回 `meeting_id/title/summary/action_items`；行动项字段为 `item_id/task/owner_name/owner_email/due_date`。
同一输入必须能生成以下两种有独立输出结构的视图。

| 视图 ID | 交付内容 | 下游可完成的任务 |
|---|---|---|
| `internal-project` | 保留已声明的行动项、负责人姓名、负责人邮箱、截止时间和英文文本 | 通过 `owner_email` 和截止时间生成分配给负责人的内部任务 |
| `external-collaboration` | 保留行动项、截止时间和处理后的英文文本；删除 `owner_name/owner_email` | 创建不依赖负责人身份字段的待分配行动项 |

已知负责人姓名和邮箱字段按确定规则保留或删除，不能依赖识别器是否检测到。
外部视图全部自由文本 `title/summary/action_items[*].task` 使用 Presidio 英文配置，将 `EMAIL_ADDRESS` 替换为 `[EMAIL]`。
`meeting_id/item_id` 使用严格受限标识格式，`due_date` 校验为日期，不能借这些字段传递任意自由文本。
外部视图不承诺去除自由文本中的所有人名、内部身份、商业机密、中文个人信息或经过混淆的邮箱。
样例必须包含藏在摘要或行动项文本中的普通英文邮箱，并明确标注处理后的预期文本。
调用方必须选择能完成其任务的视图；外部 Agent 不能依靠该视图给内部人员分派任务。

## 5. 数据可用性契约

每个视图明确输出字段、类型、必填项和额外字段处理规则；必要字段缺失时拒绝交付。
对上游原始结构执行严格校验，包括嵌套对象的未声明字段；发现结构漂移不能直接透传。
不同视图可以拥有不同结构，但不能把相同字段的类型随处理结果任意改变。
原始字段变换为新含义时，应使用清楚的新字段名和对应类型，而不是悄悄改变原字段语义。
文本处理后仍须满足输出约束；处理使必需内容失效时，应返回明确错误。
成功响应同时说明视图及契约版本，使消费方可以按确定结构处理结果。
第一版不引入用生成式模型修复数据或补全缺失事实的隐式步骤。

## 6. OPA、Presidio 与本项目的分工

| 组件 | 第一版职责 | 不负责什么 |
|---|---|---|
| OPA | 使用固定策略模板读取有限契约，根据可信身份和请求上下文输出明确决定及必需处理 | 不直接变换响应，不验证 Agent 自报身份，不解释任意自定义契约语言 |
| Presidio | 对选定自由文本识别英文邮箱，并执行契约要求的替换或遮盖 | 不决定授权，不保证发现所有个人信息或商业机密 |
| 确定性处理器 | 按视图选择和删除已知字段，执行已实现且已校验的有限操作 | 不在未知规则或处理异常时保留原值继续放行 |
| 契约执行层 | 管理版本、协调唯一授权路径、校验输入输出、处理失败并持久化交付记录 | 不证明接收方之后如何使用数据，不提供法律合规认证 |

OPA 是新流程唯一可以给出放行决定的授权引擎；旧策略引擎不能与其形成“任一通过即可放行”的关系。
常规开发者配置受限契约即可使用固定策略模板；通用 Rego 编辑平台不属于第一版。
契约引用未知规则、未知实体类型、不支持的语言或不存在的视图时，在发布前拒绝。

## 7. 开发者首次使用流程

1. 启动完整开发环境，执行健康检查，载入合成数据和受控测试身份。
2. 从会议模板声明原始结构、两个视图、授权主体和必需处理。
3. 运行契约校验与预览，对照输入和预期输出，修复错误后发布具体版本。
4. 接入已获准地址上的数据提供接口，并验证 Hub 到提供方的请求身份。
5. 使用两个调用方身份发现可申请视图，分别发起请求并执行消费样例。
6. 查看对应交付记录，模拟一次结构变更和一次服务故障，确认错误可以定位。

发现结果只描述当前可申请的视图，不保留授权，也不保证后续请求必然成功。
错误应包含稳定错误类别和可关联记录标识；面向调用方的信息不能泄露密钥、敏感原文或他人的策略详情。
普通接入不能要求开发者自行连接 OPA 决策、Presidio 处理与审计写入的内部步骤。

## 8. 一次交付的产品保证

交付依次经过当前身份及撤权检查、契约版本解析、OPA 决策、受控取数、严格输入校验、必要处理和输出校验。
在准备返回成功数据前，将交付凭据（receipt）及待处理事件（outbox）在 PostgreSQL 同一事务中持久化。
这条记录表示某份输出已验证并准备交付，不代表调用方已经收到或处理成功。
后续异步消费者从可恢复事件更新记录或转发事件；重试需要幂等处理，不能在失败后静默删除工作。
不能保证网络交付恰好一次；响应中断时以请求标识和状态帮助定位，不将“已准备”显示为“已接收”。
记录只包含必要标识、版本、规则摘要和处理状态；不得常规保存响应原文或识别出的邮箱。
必需检测、校验或交付记录持久化失败时拒绝返回业务数据；无持久化记录时不得声称已完整审计。

## 9. 版本、发布、撤权与降级

契约发布前检查语言版本、结构、规则引用、操作支持范围和固定消费样例。
已发布契约版本保持不可变；变更产生新版本，显式选择启用版本。
检查至少覆盖删除字段、字段类型变化、必填要求变化、处理变化和访问范围变化。
结构兼容性与权限变化分开报告；只有登记过消费依赖才能准确声称某个调用方受到影响。保存草案不等于激活或切换默认版本；不兼容变更不自动切换，无法判定的变更先补足证据，具体门槛见契约规格。
版本固定只固定数据语义，不能绕过当前 Agent 禁用、授权撤销或紧急停用。
OPA 或必要 Presidio 服务不可用时不走宽松处理；错误结果不能包装成处理成功。
回滚契约仅能选择仍被允许的版本；部署回滚不能重新开启已关闭的 legacy 查询入口或恢复已撤销访问。
legacy 契约需要离线校验、迁移报告和新旧输出比较；无法准确迁移的规则必须明确阻止启用。

## 10. 第一版交付范围

- 一个受控部署、一个会议数据提供方、两个预注册调用方、两个固定命名视图。
- 有限契约语言、固定 OPA 模板、已知字段投影和删除、指定文本的英文邮箱检测与处理。
- 严格输入输出校验、受控提供方地址、提供方请求身份验证、当前撤权检查、按权限查看交付记录。
- PostgreSQL receipt/outbox、可恢复且幂等的异步处理、真实服务故障测试。
- 锁定版本的官方 A2A SDK 最小适配示例；通过互操作验证后才能声明支持对应版本和交互子集。
- 容器启动方案、轻量 Python 调用封装、契约校验与预览、结构差异和消费样例检查。
- 安装文档、许可证、贡献和安全问题报告流程、持续集成及可重复执行的验收说明。

## 11. 明确延期与能力边界

- 延期：开放跨组织联邦、多租户治理、自动协商、复杂用途授权、通用策略编辑器、高级管理界面。
- 延期：中文及多语言识别、所有个人信息类型、图片或 PDF、商业机密识别、任意生成式文本安全保证。
- 延期：多种语言 SDK、大规模性能承诺、全量 A2A 能力、多区域高可用和不经验证的企业生产支持。
- 广播第一版仅接受批准的元数据通知，例如 `contract.updated` 加可公开的契约 ID/版本；事件类型和字段均为白名单，禁止任意 content、会议原文及自由文本。不能声称检测器可保证任意广播内容非敏感。
- 只有经过执行层的数据受到约束；绕过 Hub 的直接通信和接收后的数据使用不在保障范围内。
- 执行节点接触原始数据，属于受信任处理组件；后续可探索部署在提供方一侧，第一版不扩展双拓扑。

## 12. 实验版、公开试用与成熟项目

内部实验版：完整双视图示例及已知安全反例通过，可解释能力边界，尚未证明陌生开发者可独立接入。
公开试用版：真实服务测试、故障恢复、A2A 最小互操作和独立开发者接入验证通过，文档与实现一致。
成熟项目：需独立团队持续使用的证据、升级兼容记录、负载及运维数据、安全响应机制和可持续维护。
完成本轮计划最多构成公开试用基础，不自动获得“成熟”“企业级”“零泄露”或“全面合规”的结论。
后续投入以接入耗时、消费任务成功、变更与故障拦截证据决定，不以界面数量或规则数量作为主要成绩。
