# 第一次体验：让同一份会议生成两种任务清单

简体中文 | [English](BEGINNER.en.md)

不需要会写代码。你将使用项目自带的虚构会议，看到内部同事和外部伙伴拿到不同的任务信息。不会给任何人发消息，也不会创建真实工作平台上的任务。

目前这是本机演示，还没有可以点按钮操作的产品界面。结果会显示在终端（输入命令、查看运行结果的窗口）里。你可以让 AI 帮忙安装并解释结果。

## 它帮你解决什么问题？

**一份资料要交给不同的 AI 助手时，怎样让每个助手拿到该看的内容，而且这些内容还能用来完成任务？**

想象你刚开完一次项目会，要把行动项交给两个助手：内部助手需要负责人邮箱，好把任务分配给同事；外部合作助手需要知道要做什么、何时完成，但不应拿到内部负责人的姓名和邮箱。

如果直接把整份资料交出去，可能多给了不该给的信息；如果删得太多，助手又可能无法完成任务。数据格式一变，原本能运行的自动流程也可能出错。

### 打个比方：一个按清单分装、检查的资料交接台

你先给交接台一张“交付清单”：谁能来领、能领哪些字段、哪些内容要处理、交出去的资料必须长什么样。项目里的“契约”就是这张清单，“视图”就是按接收方整理出来的那一份资料。

每次请求资料时，交接台会核对领取资格，按约定整理内容，检查结果，并保存交付记录。资格不符、必要处理失败、资料不合要求，或交付记录存不下来，就停止交付并返回错误信息。它只执行事先配置的规则，不会自行判断所有内容是否敏感。

| 实际困扰 | 本项目提供的帮助 | 会议演示里的例子 |
| --- | --- | --- |
| 同一份资料，不同人能看的范围不同 | 根据当前身份和授权提供预先定义的视图 | 内部任务保留负责人邮箱，外部任务移除负责人姓名和邮箱字段 |
| 处理过的数据缺了关键字段，助手做不了事 | 检查输入和输出结构，并用样例验证下游任务效果 | 内部任务能按邮箱分配；外部任务保留截止日期，明确显示待分配 |
| 上游改字段，已有连接突然失效 | 交付时检查结构；契约发布前检查已声明的兼容性和登记样例 | 需要负责人邮箱的内部任务不能悄悄改成没有邮箱的格式 |
| 失败后不知道从哪里查起 | 返回错误类别和请求编号，供有权限的人查询诊断 | 区分没有权限、数据结构不符、处理服务不可用等原因 |

### 你现在可以体验到什么？

使用自带的虚构会议，运行后会得到两份本地任务清单：内部版有负责人，外部版待分配。它适合先体验“同一份数据，按不同规则交给不同助手”的过程；开发者接入自己的系统时，可以复用这套交付检查流程。

目前还不能直接上传任意会议文件、自动总结录音或把任务同步到真实工作平台，也没有图形操作界面。内容识别只覆盖声明的英文邮箱基线和预设字段处理，不是全面脱敏；交付记录表示系统允许尝试交付，不证明接收方已收到，也不能控制接收方后续使用。普通用户实际试用仍待验证。

## 路线一：让 AI 帮你安装（推荐）

1. 选择能读取本机文件、执行终端命令的 AI 助手，打开一个新的空文件夹。只有聊天功能的工具可以指导你，但不能替你安装。
2. 打开 [AI 安装指令](AI_INSTALL.md)，复制其中整段指令交给助手。
3. 根据提示安装并打开 Docker Desktop。它负责运行这个演示需要的配套程序。系统授权、软件许可和可能需要的重启由你本人确认，不要把电脑密码发给 AI。
4. 等助手报告安装结果。请它把两份任务结果整理成中文表格；确认内部任务有负责人、外部任务显示“待分配”。
5. 完成后告诉助手“停止本次演示，保留数据”。以后可以继续使用。

AI 的执行权限取决于你使用的工具；它不能保证下载网络、设备条件或系统权限一定满足。卡住时保留错误，不需要反复重装。

## 路线二：自己操作

### 1. 安装并打开 Docker Desktop

按你的电脑系统选择官方说明：[Mac](https://docs.docker.com/desktop/setup/install/mac-install/) / [Windows](https://docs.docker.com/desktop/setup/install/windows-install/) / [Linux](https://docs.docker.com/desktop/setup/install/linux/)。按说明完成安装，打开软件并等它启动。Windows 需要使用 Linux 容器；如果安装器提示设置 WSL 或重启，按官方说明处理。

本项目已有 Mac 本地与 Ubuntu 托管验证记录；尚未完成普通用户 Windows 安装验证。不必另外安装 Python，也不需要购买 AI API 或填写 API key。

### 2. 下载项目

打开 [项目仓库](https://github.com/Void107/A2A)，点击 **Code → Download ZIP**，解压到一个新文件夹。不要覆盖已有项目。

进入解压后的文件夹：这一层应能看到 `compose.yaml` 和 `README.md`。在该文件夹打开终端：Windows 可在文件夹空白处右键选择“在终端中打开”；Mac 可打开“终端”，输入 `cd `（末尾留空格），把文件夹拖进去再按回车。

### 3. 启动演示环境

复制下面一行到终端，按回车：

```sh
docker compose up -d --build --wait
```

第一次会下载依赖，时间取决于网络和电脑；看到很多下载文字是正常的。等命令完成且没有失败提示，再执行下一步。出现报错时先停止，不要假设成功。

### 4. 看两份任务清单

```sh
docker compose --profile demo run --rm demo
```

成功时最后会看到这一整行：

```text
PASS: public API discovery, exact dual views, local task consumers
```

它上面的两组结果分别是：

| 屏幕上的名称 | 表示什么 | 应看到什么 |
| --- | --- | --- |
| internal-project | 内部同事的任务清单 | 两项任务，有截止日期和负责人邮箱，状态 assigned（已分配） |
| external-collaboration | 外部伙伴的任务清单 | 两项任务，有截止日期，负责人为空，状态 unassigned（待分配） |

这里只处理预设字段和普通英文邮箱，不保证清除任意文本中的姓名、电话或混淆邮箱。请使用自带示例，不导入真实会议或客户资料。

没有出现 PASS 就不算演示成功。浏览器打开 `http://127.0.0.1:58000/ready` 可辅助检查就绪情况，但返回状态文字不等于完成演示；直接打开根地址也不会出现产品首页。

### 5. 用完停止，以后继续

在同一文件夹执行：

```sh
docker compose stop
```

它会停止服务、保留数据。下次先打开 Docker Desktop，再运行：

```sh
docker compose up -d --wait
docker compose --profile demo run --rm demo
```

演示会重新建立自带示例的授权；不要用它判断之前做过的“撤销权限”测试是否仍成立。不要运行删除数据卷或清空全部 Docker 资源的命令。

## 卡住时怎么办

| 现象 | 先做什么 |
| --- | --- |
| 找不到 docker 命令 | 确认已安装 Docker Desktop，重新打开终端 |
| 无法连接 Docker | 打开 Docker Desktop，等启动完成再试 |
| 提示找不到配置文件 | 回到能看见 compose.yaml 的文件夹 |
| 下载中断或超时 | 检查网络后重试启动命令；不要关闭证书校验。持续失败请把错误交给 AI 或维护者 |
| 端口或网络冲突 | 停下来，请 AI 检查；不要关闭不认识的服务或随意改配置 |
| 服务启动失败、没有 PASS | 保留最后的错误文字，请 AI 解释，不要清空数据重装 |

求助时提供操作系统、停在哪一步和去除敏感信息后的错误即可。不要发送 `.env`、密钥、令牌、密码或完整电脑日志。
