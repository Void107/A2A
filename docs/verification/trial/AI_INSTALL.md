# 复制给 AI 的安装指令

适用于能访问本机目录并运行命令的 AI 助手。复制下面整个文本框。普通聊天助手可以解释步骤，实际操作仍由你完成。

```text
请帮我在本机体验 A2A Contract Hub。我不熟悉编程，请用简单中文说明进度，每次需要我操作时只给一个明确步骤。

项目：https://github.com/Void107/A2A
目标：运行项目自带的合成会议演示，看到内部任务有负责人、外部任务待分配，并把真实结果解释给我。只在本机运行，不部署公网，不接真实资料或工作平台，不推送代码。

请按顺序执行：
1. 确认我的操作系统、当前目录及已有安装。先检查是否已有本项目、Docker 和 Compose，保留现有文件与数据。不要覆盖旧目录、切换已有项目版本、更新工作树或重置改动；若已有演示服务或同名 a2a-alpha-local 资源，先说明并让我选择是否复用。默认只在我选择的新空目录获取官方仓库代码，记录实际提交号；ZIP 下载则记录来源和获取时间。
2. 读取项目 AGENTS.md、README.md 和 docs/verification/trial/BEGINNER.md。当前只安装和体验，不自动执行开发改造任务。
3. 若缺少 Docker Desktop，给出适合我电脑的 Docker 官方安装页面，指导我完成安装和启动。系统密码、许可、提权与重启让我本人操作。不要绕过权限、关闭安全保护或从不明来源下载安装脚本。确认 docker version 能连到服务，docker compose version 可用。不必在宿主机另装 Python。
4. 在有 compose.yaml 的仓库根目录运行 docker compose up -d --build --wait。解释下载可能需要等待，失败时读取相关错误定位，不把失败当成成功。不读取或打印 .env、/state 下密钥或其他私密文件。不删除数据卷，不运行全局 prune，不停止无关容器。遇到端口或网络冲突先报告，不盲目修改安全配置。下载失败不得禁用 TLS 校验或解除锁定版本；需要复杂修复时先向我解释。
5. 启动成功后运行 docker compose --profile demo run --rm demo。它会建立或恢复合成示例授权；如果发现已有撤权实验，先说明影响。只有命令退出 0 且实际出现 PASS: public API discovery, exact dual views, local task consumers 才报告演示通过。
6. 用真实输出整理中文表格：任务、截止日期、内部负责人、外部负责人（为空就写“待分配”）。不编造输出，不猜测外部负责人。告诉我当前没有图形操作界面，浏览器 /ready 只是就绪检查。
7. 请我亲自看表格，用一句话说内部和外部结果的区别。区分 AI 代做、我亲自操作和仍未完成的项目，不能替我填写真人体验反馈或宣称 AC-22 验收通过。
8. 最后告诉我代码所在文件夹、版本、成功或失败的证据，以及如何用 docker compose stop 停止、docker compose up -d --wait 继续。问我是否现在停止；停止时保留数据。不要为追求成功而删除数据、修改权限或改业务代码。

输出不要包含密码或令牌。卡住时报告具体原因与我下一步需要做的事，不无限重试。不要承诺固定安装时长。
```
