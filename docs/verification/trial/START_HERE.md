# 试用入口

- 不熟悉编程：先看 [普通用户体验指南](BEGINNER.md)，可复制 [AI 安装指令](AI_INSTALL.md)。
- 希望验证开发接入：继续下面的完整任务。

两条路线分开记录；AI 辅助演示不能替代完整 AC-22 验收。

## 独立开发者试用任务

状态：材料已准备，尚未真人执行。由项目所有者安排参与者；托管 CI 已通过，私密安全报告渠道已启用；真人接入结果仍待验证。

目的：验证开发者能否独立接入、得到可完成任务的数据，并理解契约变更或访问被拒绝的原因。只使用仓库合成会议数据，不连接真实任务平台。

## 参与条件与记录

参与者未参与本项目实现。开始前记录匿名编号、操作系统、相关开发经验和包内 MANIFEST 的摘要。征得同意后才记录观察；不录制凭据、终端令牌或个人信息。可以随时退出。观察者不主动指导，参与者求助时记录时间、问题和帮助程度。

将 observation.template.json 复制为独立记录文件。空白和未完成保持 null，不能补填推测时间。依赖下载耗时与实际接入耗时分开计时。“30 分钟接入”是待验证目标，不能预填为结果。

## 任务顺序

1. **独立启动。** 按根目录 README 的在线或离线步骤取得固定依赖并启动。记录选择的路径、首次启动时间；访问 /health 和 /ready，解释两者有什么区别。卡住时先记下错误和已尝试的步骤。
2. **配置提供方和调用方。** 找到示例提供方的地址及批准地址配置，说明更换同类型数据提供方要改哪些配置。运行示例预置两个调用方，再使用轻量客户端完成一次发现和固定版本查询。常规接入不改 Hub 源码、不编辑内部 Rego；如果不得不修改，记录文件和原因。
3. **完成两种业务任务。** 内部视图创建两项任务并按邮箱分配，核对日期；外部视图创建两项待分配任务，核对日期且不猜测真实负责人。记录实际任务结果，说明被删除字段如何影响下游行为。
4. **理解一次拒绝。** 使用合作调用方请求 internal-project。记录错误类别、request_id，尝试查询自己有权查看的诊断；说明下一步应修改请求还是申请权限。不要为了通过而更换为管理员身份。
5. **修改一次契约。** 复制合成契约，在副本里同时移除内部视图的 owner_email 投影、输出字段定义与对应 required 项，并递增版本。通过契约比较工具查看分类；说明现有内部消费者为什么受到影响，以及为什么保存草案不等于激活或切换默认版本。保留草案，不绕过迁移检查。
6. **重启并复查。** 重启服务，确认既有记录仍在、双视图仍可用。停止试用环境；只有明确属于本次试用的资源才能清理。

比较工具入口：`python scripts/contract_tools.py compare <原契约> <草案>`。容器运行和轻量客户端入口见 README、examples/meeting_views/demo.py 与 sdk/client.py；凭据只保留在本地，不贴入观察报告。

## 完成判定

每项分别记录 completed / blocked / not_started；不能用“演示脚本通过”代替参与者独立接入成功。观察者记录求助次数、所需业务代码行数、Hub 源码修改数、理解错误的原话摘要，以及内部/外部任务的实际效果。

遇到问题先归类为文档、安装、接口理解、权限、契约变更或程序缺陷，再填写复现步骤与修正建议。修复后只重跑受影响自动验收，并让参与者复查有问题的任务。

结束时询问：哪个步骤最费力？哪些信息让你确认结果可用？若没有 Hub，你会自己写哪些连接代码？这些回答用于决定后续产品投入，不把单人试用外推成市场验证。
