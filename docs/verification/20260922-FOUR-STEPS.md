## 1. 安全与失败边界

- 10 种非法契约分别在保存、服务端校验、伪造 validated 状态后的激活阶段拒绝；没有 active 遗留。新增安全 rule 代码定位失败规则，不输出用户提交值。
- 五类接口交叉验证缺凭证、无效/过期/错误签名 token、无 scope、停用身份；已签名的组织/角色自述不能覆盖数据库身份，当前写权限也不能覆盖他人契约所有权。
- 实际 TLS 服务检查证书信任与主机名；连接固定到批准 IP 后保留原 Host/SNI。未信任证书和错误主机名在 HTTP 业务请求前拒绝。
- 真实 TCP 故障代理只注入错误状态、非法 JSON、延迟；所有成功响应仍来自实际 OPA/Presidio。真实 OPA 停止后拒绝，重启后重新授权；调用中途恢复也有验证。
- 生产查询入口验证响应字节上限 -1 / 恰好 / +1、非法 JSON、持续滴流总超时、8 个占用槽位与第 9 请求拒绝、释放后恢复。错误中没有业务数据。

完整本地 CI：12 个子命令全部退出 0，默认 125 项测试通过；包括真实 PG/Redis、迁移、未迁移库、签名/TLS、持久化/进程退出、OPA/Presidio、完整交付和官方 SDK。执行清单、时间、退出码与当前代码 SHA256 在 `docs/verification/ci-run-a5edbe801e/`。API 矩阵和边界助手由 verify_delivery.py 实际调用，不是未收集的独立样例。
